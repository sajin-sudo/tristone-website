# TriStone: private test before launch

The hardened system needs a Hostinger Node gateway, the existing private Sites Worker, D1/R2, and the newly configured submission-only Google backend. A static ZIP upload alone cannot preserve secure owner editing. Earlier DNS instructions and the frozen export do not describe this hardened version.

No deployment, Google authorisation, domain connection or DNS change is authorised by this security task. The current live website remains unchanged.

Follow SECURITY-MANUAL-SETUP.md for exact manual settings. Configure an explicitly approved HTTPS test origin on both servers. Configure the password hash and authenticator secret privately, apply the new D1 migration, and obtain a valid server-only Sites service-access credential.

After separately authorising a private test deployment, verify owner login, editing, image upload, logout, CAPTCHA rejection, actual customer records and actual candidate PDFs. Keep the two Google destinations separate. Public deployment and domain changes require subsequent owner authorisation.
